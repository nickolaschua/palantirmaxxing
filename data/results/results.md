# Results

Generated PEC JSON follows [pec-result/1](../../contracts/pec.md). The file command writes `pec-example.json` when following the README example. `pec-benchmark.json` contains separate runtime and sensitivity measurements from the benchmark utility. Deterministic exposure results contain no timing information.

Generated outputs are ignored by default, with explicit exceptions in `.gitignore` for curated benchmark, golden handoff and sensitivity artifacts. The small PEC reference result is versioned under `contracts/examples/pec-result.json`; benchmark findings are recorded in `docs/specifications/pec-benchmark.md`. Inputs remain in `data/scenarios/`. No API transport is implemented.

`static-mvp-benchmark.json` is the versioned benchmark snapshot generated by
`scripts/benchmark_static_mvp.py`. It contains the complete unrounded static
scenario result, the 50-row candidate evidence and seven measured timing rows.
The versioned snapshot is documented in
`docs/specifications/static-mvp-benchmark.md`. Frontend integration remains
unimplemented.

The coverage investigation writes `pec-coverage-comparison.json`, separate `pec-coverage-timing.json`, recovered `pec-coverage-episode.json`, and diagnostic PNG/SVG files here. These generated files remain ignored. Versionable report snapshots live beside `docs/specifications/pec-coverage-investigation.md`.

`static-mvp-planning-result.json` and `demo-planning-result.json` are versioned
`planning-result/1` handoffs, with separate `*-benchmark.json` timing snapshots.
`mvp-sensitivity.json` records the tested synthetic parameter grid. The sole
frontend contract is [API-DESIGN.md](../../frontend/docs/API-DESIGN.md); reproduction
commands and the separate demo scenario are described in the
[backend demo summary](../../docs/DEMO_BACKEND_SUMMARY.md).
